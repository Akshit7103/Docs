## 2. Ingestion — step 1

**Open the Action:** [OTC - Ingest Email](https://nomuraevalinstancegenaipov.service-now.com/sys_hub_action_type_definition.do?sys_id=c8bb4b1987df4d08adcf55376641ad0e)

Look at the script step. It is about ten lines, and the operative one is:

```javascript
var m = new x_nose_nfotc_bsm.EmlFieldExtractor().mailContents(attId) || {};
```

That is the pattern for the whole application. Now the file it calls.

**Open:** [`EmlFieldExtractor`](https://nomuraevalinstancegenaipov.service-now.com/sys_script_include.do?sys_id=48dff75b591148bc86a47b311d7709d8) — 860 lines

**Find:** `mailContents: function` *(L505)*

860 lines, and it is that big because real mail is a mess. Two defects from your actual mails:

1. **A stale MIME boundary.** The gateway rewrote the message and left an `X-Original-Content-Type`
   header pointing at a boundary that no longer existed. Split on it, get an empty body.
2. **Quoted-printable.** The body arrived as `=3D` / `=0A` escapes. Undecoded, every amount and date is
   unreadable.

**Neither threw an error.** That is the point to land: an ingestion bug is silent, and an undecodable
mail looks exactly like an empty one.

**Find:** `threadState: function` *(L577)* — the thread verdict, which step 2 then uses.

## 3. Classification — step 2

**Open the Action:** [OTC - Classify / Identify](https://nomuraevalinstancegenaipov.service-now.com/sys_hub_action_type_definition.do?sys_id=dad37e87fe8b4869b88b16b01207527a)

Its own comment: *"Thin delegate — logic lives in WizardExtractor.identify so it stays testable and
single-sourced."* Read that out, then open the file.

**Open:** [`WizardExtractor`](https://nomuraevalinstancegenaipov.service-now.com/sys_script_include.do?sys_id=ea6c64b7e24f4f81ad24c401a4b62926) — 821 lines, the most important file in the app

### 3.1 Three toggles, then five tests

**Find:** `identify: function` *(L134)*

First, three switches read off the work driver's own configuration — all default ON:

```javascript
var exReplies = (t0.excludeReplies === undefined) ? true : !!t0.excludeReplies;
var exNoise   = (t0.excludeNoise   === undefined) ? true : !!t0.excludeNoise;
var exThreads = (t0.excludeThreads === undefined) ? true : !!t0.excludeThreads;
```

Then the chain. **Rule 1 is one line, right there:**

```javascript
if (exReplies && /^\s*(re|fwd?|fw)\s*:/i.test(subject)) { ... reason = 'reply_forward'; }
```

### 3.2 The thread rule — the deepest and best bit

**Find:** `_isThreadMail` *(L320)* -> it calls `EmlFieldExtractor.threadState()` -> `_hasQuotedHistory()`
-> **`THREAD_MARKERS`** *(L559)*

Eight patterns. Open that array — it is the most interesting twenty lines in the codebase:

| Pattern | Catches |
|---|---|
| `--- Original Message ---` | Outlook |
| `_____` then `From:` | Outlook variant |
| `From:` ... `Sent / Date / Gesendet / Envoyé / Enviado / Inviato / 送信日時 / 보낸사람:` | **multilingual** |
| `Von / De / Da / От:` ... | non-English clients |
| `On ... wrote:` | Gmail, Apple |
| **two consecutive `>` lines** | plain-text quoting |
| `divRplyFwdMsg`, `gmail_quote`, `yahoo_quoted`, `moz-cite-prefix` | HTML clients |

**Three measured numbers are written into the comments around it.** These are the credibility moments:

- *headers alone would throw away **11% of real work*** — so reply headers only downgrade a mail to
  `reply` (kept and visible), they never drop it.
- *Thread-Index / Thread-Topic are **not** usable: Outlook stamps them on fresh mails too — **75 of 107**
  here.*
- *the gateway stamps its banner into every alternative, so counting over the whole MIME source flags
  **80 of 107** fresh mails* — which is why the count is taken on one decoded part.

And the single `>` case, with its own comment: one `>` is decoration, not quoting — **a real SSI-change
notice reads `">>>SSI will become>>>"` and must not be dropped.** Two consecutive `>` lines are
required.

The verdict is cached on the record (`thread_state`) so a re-sync never re-reads the attachment.

### 3.3 Noise domains

**Find:** `_isNoiseDomain` *(L335)* — pulls the domain off the sender, compares against the
`noise_domains` system property, and matches subdomains as well as exact. Editable without a release.

### 3.4 The label loop — cheap tests first, the model only if needed

**Find:** the `for` loop over `labels` *(L169)*. Per label, in order:

| Order | Test | Cost | Reason recorded |
|---|---|---|---|
| 1 | `_anyMatch(L.exclusions, ...)` | free | skip this label |
| 2 | subject keywords / body keywords / sender list | free | `rule_match` |
| 3 | `L.context` -> `GenericFieldExtractor.classifyMatch()` | **one model call** | `ai_context` |
| 4 | label with no criteria at all | free | `empty_label` |

**This is the "we do not spend a model call unless we have to" argument, in code.** Deterministic
keyword tests run first; the LLM is a *fallback*, used only for a label that has a plain-language
context and where the keywords did not already decide.

### 3.5 Ten outcomes, not five

Every path returns a **named reason**: `no_email`, `no_rules`, `default`, `reply_forward`,
`quoted_thread`, `noise_domain`, `rule_match`, `ai_context`, `empty_label`, `no_label_match`.

### 3.6 The verdict lands, and is audited

**Find:** `_persistClassification` *(L217)* — and read the comment above the call site:

> a DROPPED mail must still carry its verdict, otherwise it is indistinguishable from one the system
> never saw

**Find:** `_auditClassification` *(L240)* -> writes `classification.decided` with label, reason, prompt
reference and content hashes.

**Show it live:** [classification.decided events](https://nomuraevalinstancegenaipov.service-now.com/x_nose_nfotc_bsm_audit_list.do?sysparm_query=event_type%3Dclassification.decided%5EORDERBYDESCsys_created_on) — open one row, read `ai_attributes`.

### 3.7 It is configuration

**Find:** `routeForWizard` *(L197)*. The labels, keywords, senders, exclusions and AI contexts all come
from the work driver's **Email Identification Rules** JSON. [Open a wizard record](https://nomuraevalinstancegenaipov.service-now.com/x_nose_nfotc_bsm_wizard_list.do) beside it.

## 4. Counterparty — step 3

**Open the Action:** [OTC - Extract Counterparty](https://nomuraevalinstancegenaipov.service-now.com/sys_hub_action_type_definition.do?sys_id=3ec4affde3754ebd93ace5eb3accf282)

**This one has no Script Include.** The whole capability is the Action, about twenty lines. Worth
saying out loud: not everything delegates. When the logic is a directory lookup and nothing more, it
lives here — and you can read the entire capability on one screen.

Read its header comment:

> Counterparty is **DERIVED from the sender** via the counterparty directory (**not AI-extracted**).

Say that plainly, because it is a governance point: **the model never guesses who the counterparty is.**
It is looked up from the sender's email address against the directory. No address in the directory, no
counterparty — the field stays blank rather than being invented.

And there is a second real-mail defect recorded in the comment below it:

> Some mails fold the `From` header across two lines, so `sender` holds only the display name while
> `mail_from` carries the address — search both so the lookup always sees the address.

**This step is also why every match lands at Tier 3.** The directory in this environment is synthetic,
so the lookup finds nothing, the counterparty stays blank, and tiers 1 and 2 — which both need it —
can never fire. Make that point here, where the cause is visible on screen, and it will already be
answered when you reach the matching numbers.

## 5. Extraction — step 4

**Open the Action:** [OTC - Extract Fields](https://nomuraevalinstancegenaipov.service-now.com/sys_hub_action_type_definition.do?sys_id=3b94d9c953c44eb68f7dd94ac607ade0)

Its comment: *"Thin delegate — runs the wizard's own field prompts via WizardExtractor.extractEmail
(one AI call ...)"*. Ten lines again. But this one goes **three layers deep**:

```
Action
 └─ WizardExtractor.extractEmail()      the spine
     └─ GenericFieldExtractor           chunking, fan-out, retry
         └─ RowSegmenter                where a cashflow row starts and ends
         └─ global.ChinouClient         the model call
```

Worth saying out loud: the flow shows four steps; step four alone is three layers, and that is where
the engineering is.

### 5.1 The spine

**Find (WizardExtractor):** `_processEmail` *(L348)* — picks the sources on the mail, runs each through
its own reader, merges, dedupes, writes cashflows. **It deletes the mail's existing rows before
rewriting them** — remember that for 5.4.

### 5.2 Why one call is not enough

**Open:** [`RowSegmenter`](https://nomuraevalinstancegenaipov.service-now.com/sys_script_include.do?sys_id=b3ad6b378272411d88e057e8275b778d) — 307 lines

**Find:** `segment: function` *(L56)* — finds row boundaries in three body shapes (plain lines, blocks,
flattened HTML table rows), **anchored on the amount**, because that is the one thing every cashflow
has.

**Find:** `planCalls: function` *(L236)* — planning is **time-based, not size-based**: a fixed cost plus a
per-row cost, worked backwards from the time budget a single call is allowed.

### 5.3 The retry that shows judgement

**Open:** [`GenericFieldExtractor`](https://nomuraevalinstancegenaipov.service-now.com/sys_script_include.do?sys_id=61f6aeecb16847a49b3683c74df74aec) — 369 lines

**Find:** `lost.length < items.length` *(L198)*

```javascript
if (lost.length && lost.length < items.length) {   // retry ONLY if some chunks succeeded
```

- **Some failed, some worked** -> transient. Retry the failures, at lower concurrency.
- **All failed** -> not transient. The service, the credential or the prompt is broken. Retrying would
  waste time and bury the real fault, so it does not.

**Find:** `(retry)` *(L252)* — a retried chunk keeps its **original** number, so the log reads
`chunk 4/8 (retry)`. You can reconstruct a run afterwards.

### 5.4 It checks its own work

**Find (WizardExtractor):** `extraction_status` *(L499)*

Fewer rows back than the segmenter counted -> the mail is flagged **partial**. And the next line
**clears** the flag when a later run recovers them. A warning that never clears is one people ignore.

**Show it live:** [mails flagged partial](https://nomuraevalinstancegenaipov.service-now.com/x_nose_nfotc_bsm_email_list.do?sysparm_query=extraction_status%3Dpartial)

### 5.5 Not everything goes to the model

**Open:** [`XlsxCashflowExtractor`](https://nomuraevalinstancegenaipov.service-now.com/sys_script_include.do?sys_id=6b0038a1a3044be6bd8043def95cd276) **Find:** `extract: function` *(L64)*

An Excel attachment is never sent as a file. It is parsed in-platform into a text grid, then joins the
ordinary text path. **A document cannot be chunked; text can** — so Excel inherits the segmentation,
the retry and the completeness guard for free.

### 5.6 What it cost

[LLM usage](https://nomuraevalinstancegenaipov.service-now.com/x_nose_nfotc_bsm_llm_usage_list.do?sysparm_query=ORDERBYDESCsys_created_on) — one row per call, real cost and latency from the service, chunks counted
individually.

## 6. Compare & Match — the separate flow

**Open:** [OTC Match & Write-back (Wizard-driven)](https://nomuraevalinstancegenaipov.service-now.com/sys_hub_flow.do?sys_id=7ae1ef7b4ae846fc9cd1d29bb200037a) then the Action
[OTC - Compare & Match](https://nomuraevalinstancegenaipov.service-now.com/sys_hub_action_type_definition.do?sys_id=5f8ca1ce82374e57a1a5bd4783baf502), which calls:

```javascript
var r = new x_nose_nfotc_bsm.CompareMatch().matchEmail(inputs.email_record);
```

**Open:** [`CompareMatch`](https://nomuraevalinstancegenaipov.service-now.com/sys_script_include.do?sys_id=a0999b1fd30a42628d5c158080d039e6) — 988 lines. Two screens only.

### 6.1 Three tiers

**Find:** `Tier 1 (exact)` *(L73)*

| Tier | Amount | Value date | Counterparty |
|---|---|---|---|
| **1** | exact | exact | exact |
| **2** | +/- 50 | +/- 2 **business** days | fuzzy >= 0.85 |
| **3** | exact | exact | **dropped** |

Tier 2 is the only tier with tolerance. First hit wins.

**Then read the comment right below** — the code documenting its own gaps against the spec:

> **KNOWN FSD GAPS (data not available):** business days skip weekends only, **not** currency or bank
> holidays (no holiday calendar); the amount tolerance is in raw currency, not the FSD's "$50
> equivalent" (no FX rates). Both upgradeable via config plus a rate/calendar source, with no rewrite.

### 6.2 The guard

**Find:** `match: function` *(L174)* — twenty lines, three tries. And at the top:

```javascript
if (!cf.currency || !cf.direction) { return out; }
```

Blank direction would let the query match a booking of **either** direction and present it as a Tier-1
exact — a confident, wrong answer. So it returns `no_match` instead. **Better to allege than to match
the wrong way round.** Blank counterparty drops to Tier 3 rather than faking a confirmed one.

### 6.3 Tolerances are configuration

**Find:** `loadConfig: function` *(L89)* — date window, amount tolerance, name threshold, all from the
config store with a per-work-driver override. [Match config](https://nomuraevalinstancegenaipov.service-now.com/x_nose_nfotc_bsm_config_list.do?sysparm_query=keyLIKEmatch)

### 6.4 Where it stands

**109 of 124 (87.9%), all at Tier 3** — because the counterparty directory here is synthetic, so tiers
1 and 2 can never fire. Data, not code.

Of the 15 misses: **8 are netting granularity** — the mail lists legs, the booking is one netted total,
and they sum **exactly**. 4 are a real extraction error, 3 had no value date.

The 8 are a question for them, not a bug: at what granularity should a netted booking match?

## Questions to expect

| Question | Answer |
|---|---|
| What if the model is wrong? | Nothing auto-commits. Every cashflow lands `awaiting_confirmation`; an analyst confirms, and that is audited with the AI value beside theirs. |
| Can we add our own mail types? | Yes — identification rules and field prompts are configuration on the work driver record, not code. |
| Does every mail cost a model call? | No. The reply, thread and noise tests are free, and keyword rules are free. The model is only used for a label with a plain-language context that the keywords did not already decide. |
| What if a mail is too big? | Segmented and processed in chunks against a time budget; if rows still go missing the mail is flagged `partial` rather than reported complete. |
| Which PDFs work? | Those with a real text layer. Image-only PDFs are not supported — no OCR in the path — and we flag them rather than guess. |
| Why is everything at the widest tier? | The counterparty directory here is synthetic. Tiers 1 and 2 need real counterparty data; the logic is unchanged. |
| What about netted bookings? | Today: no match, and we can show the legs sum exactly. Which granularity wins is your policy decision. |
| How do we know what it cost? | The usage table — real figures from the service, per call. |

## The six moments that land

1. **"Thin delegate"** — the Action comment. Frames the session: the flow is the shape, the Script
   Include is the thinking.
2. **The MIME war story** — a rewritten boundary and quoted-printable, both producing an empty body
   with *no error*.
3. **`THREAD_MARKERS` and its comments** — eight patterns, multilingual, three measured numbers. The
   `">>>SSI will become>>>"` note proves it came from real mail.
4. **Counterparty is looked up, never guessed** — and it is the visible cause of every Tier 3 match.
5. **`lost.length < items.length`** — retry when *some* chunks worked, never when *all* failed.
6. **The blank-direction guard** — better to allege than match the wrong way round.
